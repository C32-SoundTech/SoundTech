### 需求规格说明书（V2.0）
##### SoundTech® by Dingdust 2025.10.23
---

本文档在 V1.0 版《需求规格说明书》的基础上进行全面升级，延续“答题平台”的核心能力，新增“多智能体与RAG知识库”“中台API改造与测试”“前端问答界面与接口接入”等能力，旨在将原有系统服务升级为面向个性化学习与智能助教的综合平台。

---

一、文档目的与范围
- 文档目的：明确 V2.0 系统的功能需求、接口与数据扩展、非功能目标与验收标准，为设计、开发、测试与部署提供统一依据。
- 适用范围：全体研发成员（后端/中台/前端/测试/运维）、合作方与试点教师团队。
- 术语与缩写：
  - RAG：Retrieval-Augmented Generation，检索增强生成；
  - 多智能体：通过编排与协作实现复杂任务分解、工具调用与状态管理；
  - 中台：提供稳定可复用的业务能力和API接口层；
  - KB：Knowledge Base，知识库；
  - UGC：用户生成内容（用户笔记、提问、纠错等）。

---

二、与 V1.0 关系与继承
- 继承与兼容：V2.0 完整继承 V1.0 的题库管理、账号体系、答题与历史统计、收藏与错题本、定时与考试模式等核心能力，保持数据与接口向后兼容。
- 升级方向：
  1) 在“答题平台”之上叠加“AI题目答疑”与“个性化RAG知识库”；
  2) 引入多智能体工作流（学习规划、题目讲解、错题巩固、考试评估）；
  3) 中台API统一改造与自动化测试；
  4) 前端问答界面与接口接入，支撑可视化与交互体验升级。

---

三、总体目标与完成度规划
- V2.0系统后端-多智能体-知识库系统搭建（60%）
  - 系统选型与探索（25%）
  - RAG知识库搭建（15%）
  - Tool工具库编写（10%）
  - 工作流设计（15%）
- V2.0系统中台-API接口与测试（25%）
  - API接口改写（15%）
  - API接口测试（10%）
- V2.0系统前端-界面设计与接口接入（15%）
  - 前端问答界面设计（5%）
  - 前端接口接入测试（10%）

注：百分比为整体工作量占比与阶段目标完成度计划，用于阶段汇报与里程碑管理。

---

四、系统架构与技术选型（延续与升级）
- 技术栈延续：Python、Flask（或Flask+waitress/uWSGI）、CSV+SQLite 持久化、模板化前端（HTML+CSS+JavaScript）。
- 新增/强化组件：
  - 多智能体编排：以轻量化 Python 方案实现任务分解、记忆、工具调用与状态追踪（结合现有 `rag_agent/` 目录能力）。
  - RAG服务：基于题库与用户历史构建检索索引，支持个性化上下文拼接与答案生成。
  - 中台API：统一鉴权、速率限制、可观测与测试覆盖。
  - 前端问答界面：面向“AI题目答疑”的新UI，支持会话、引用证据与反馈标注。
- 非功能：
  - 并发目标：10秒内支持至少100个用户同时访问（沿用V1.0指标）。
  - 安全合规：口令哈希、参数化查询、会话管理与敏感数据最小化暴露。
  - 部署：HTTPS证书（`static/localhost.crt/key`仅为开发证书），生产环境通过OpenSSL或云证书管理。

五、详细需求说明

5.1 后端-多智能体-知识库系统（60%）
A) 系统选型与探索（25%）
- 目标：明确多智能体编排方式、状态管理与工具调用机制；评估与现有代码的耦合度与迁移成本。
- 要求：
  - 智能体角色划分：
    - 学习规划Agent（制定目标、推荐题目、安排练习节奏）；
    - 讲解Agent（解析题干与选项，生成解释，关联RAG证据）；
    - 巩固Agent（错题巩固与复习建议）；
    - 评估Agent（考试评分、薄弱项识别与建议）。
  - 状态与记忆：用户画像/当前会话上下文/历史记录聚合；
  - 工具接入：题库检索、历史查询、收藏管理、RAG检索、统计分析等。
  - 兼容性：与 `handlers/`、`rag_agent/` 既有目录结构兼容，最小侵入。

B) RAG知识库搭建（15%）
- 数据来源：
  - 题库（`resources/questions.csv`、Excel经转换CSV、`tools/convert_txt_csv.py`）；
  - 用户历史（答题记录、错题、收藏、标签）；
  - UGC（用户笔记/纠错/提问）。
- 索引结构：
  - 基础索引：题目stem/选项/解析（如有）；
  - 个性化索引：基于用户错题、收藏与薄弱类别的加权检索；
  - 证据存储：引用来源、置信度、时间戳、命中字段。
- API输出：返回答案（或解析草稿）、引用证据、召回列表与置信度。

C) Tool工具库编写（10%）
- 工具类别：
  - `QuestionStoreTool`：题库检索与过滤（类别、难度、关键词）。
  - `HistoryTool`：查询/写入用户作答历史、错题与收藏。
  - `RAGSearchTool`：个性化检索与证据聚合。
  - `ExamTool`：考试会话管理与评分。
  - `AnalyticsTool`：正确率、薄弱项、近期考试统计。
- 要求：统一输入输出结构、错误码与日志；支持限流与超时；具备可测试性。

D) 工作流设计（15%）
- 关键流程：
  - AI题目答疑：
    1) 解析用户问题（题号/关键词/类别）；
    2) 触发RAG检索，生成初稿；
    3) 讲解Agent完善答案，附证据；
    4) 用户反馈（有用/无用/标注错误）进入UGC池与索引增量更新。
  - 错题巩固：根据历史错题定期推送与练习建议。
  - 考试评估：创建会话、计时、评分与报告生成（接入现有 `exam_sessions`）。
- 追踪与观测：工作流ID、步骤事件、耗时与结果持久化；失败重试策略。

5.2 系统中台-API接口与测试（25%）
A) API接口改写（15%）
- 鉴权与会话：统一 `session['user_id']`，未登录时携带 `next` 参数重定向。
- 新增/改写接口示例：
  - `POST /api/qa/ask`：AI题目答疑（入参：问题文本/题号/上下文；出参：答案、证据、置信度）。
  - `GET /api/rag/sources`：检索引用来源列表与命中详情。
  - `POST /api/feedback`：用户反馈（有用/无用/纠错），更新UGC与索引。
  - `GET /api/analytics/user`：个人统计（正确率、薄弱项、近期考试）。
  - `POST /api/workflows/run`：触发指定工作流（类型：答疑/巩固/评估）。
- 错误码与返回体：统一 `code`、`message`、`data`；明确参数校验、权限与速率限制。

B) API接口测试（10%）
- 覆盖范围：
  - 单元测试：工具库、检索与评分逻辑；
  - 集成测试：主要API端到端（鉴权、入参校验、结果断言）；
  - 回归测试：与V1.0接口行为保持一致的关键路径（登录、答题、历史、收藏、统计）。
- 数据准备：构造小型题库与用户历史；模拟错题与收藏；准备UGC样例。
- 目标：通过率≥95%，关键接口失败率<1%。

5.3 前端-界面设计与接口接入（15%）
A) 前端问答界面设计（5%）
- 交互元素：
  - 问题输入框（支持题号/关键词）；
  - 答案展示区（高亮关键点、引用证据折叠/展开）；
  - 反馈按钮（有用/无用/纠错）；
  - 会话侧栏（历史问答、固定锚点）。
- 可用性：与 `templates/` 现有风格一致（`base.html` 继承），响应式布局。

B) 前端接口接入测试（10%）
- 接口联调：`/api/qa/ask`、`/api/rag/sources`、`/api/feedback`、`/api/workflows/run`。
- 可靠性：空态处理、错误提示与重试；加载态与节流；防止重复提交。
- 可观测：记录接口耗时与命中条数，前端日志脱敏。

六、数据模型扩展（在原有基础上增量）
- 新增/扩展表：
  - `user_profiles`（画像与偏好，含薄弱类别与最近练习偏好）；
  - `ugc_feedback`（用户反馈：类型/内容/目标ID/时间戳/有效性）；
  - `rag_indexes`（索引条目：来源ID/命中字段/权重/更新时间）；
  - `agent_runs`（工作流运行：流程ID/步骤/耗时/结果/状态）；
- 约束与安全：UNIQUE约束避免重复；审计字段（created_at/updated_at）；严格参数化查询。

---

七、非功能需求
- 性能：
  - RAG检索平均响应时间≤1.5s（在100并发场景下，缓存与预热）；
  - API 99%分位响应≤2.0s；
- 安全：
  - 身份鉴权与会话管理；
  - 防SQL注入、XSS与CSRF（模板转义、令牌校验、SameSite Cookie）；
- 可用性与可维护：
  - 监控与日志：结构化日志、错误分级与报警；
  - 配置管理：`rag_agent/config/` 统一管理，支持环境变量覆盖。

---

八、测试与验收
- 测试计划：单元/集成/回归/压力测试；
- 验收标准：
  - 功能覆盖：“AI题目答疑”完整闭环（提问-检索-生成-证据-反馈-索引更新）；
  - 兼容性：V1.0关键功能无回归；
  - 性能与安全：满足非功能指标；
  - 文档与交付：API文档、工作流说明、部署清单与演示脚本齐备。

十、风险与假设
- 假设：题库与用户数据可用于个性化索引；试点环境可部署HTTPS；
- 风险：模型或检索质量不稳定、接口耦合过高、前端体验复杂度上升；
- 应对：灰度发布、A/B评估、缓存与降级策略、接口版本化与兼容层。
